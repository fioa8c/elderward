Elderward

Um único arquivo PHP que encontra o que se infiltrou num site WordPress, arranca o malware que conhece e lê os logs de acesso para mostrar por onde ele entrou.

$ curl -O https://raw.githubusercontent.com/fioa8c/elderward/main/elderward.php
$ php elderward.php scanall=1 scandirectory=/path/to/wp-root

Ver o código no GitHub Ver o código do elderward.php

Primeira olhada num servidor comprometido

scanall=1 roda todos os scanners sem alterar nada e imprime uma lista só, do mais grave ao mais leve. O código de saída diz ao cron e ao CI o tamanho do estrago.

investigator@host: /var/www/html 

      

    


    

      
Sete maneiras de olhar

      
Cada modo de varredura é uma flag. Eles rodam separadamente, exceto o scanall, que roda todos e também pode incluir seus logs.


      

        

          
Limpeza por assinaturaphp elderward.php

          
Percorre a árvore de arquivos e identifica injeções conhecidas, como as campanhas JavaScript ndsw/ndsx e wqpq, e as remove. Adicione dryrun=1 para ver antes o que seria alterado.

        

        

          
Tudo, só relatórioscanall=1

          
Todos os scanners numa passada, do mais grave ao mais leve. A limpeza por assinatura é forçada a rodar em modo de simulação e restore=1 é ignorado, então nada no disco muda.

        

        

          
Integridadescanintegrity=1

          
Compara o core do WordPress, cada plugin e cada tema com o pacote oficial do wordpress.org da versão instalada. Aponta arquivos modificados, ausentes e sobrando. PHP sobrando dentro do core ou de um plugin é o clássico webshell plantado. Funciona offline com checksumdir=.

        

        

          
Logs de acessoscanlog=/var/log/apache2

          
Lê todos os logs de acesso de um diretório, inclusive .gz, em busca de acessos a webshells, PHP servido de uploads, exploits de wp-file-manager, Slider Revolution e TimThumb, sondagens de .env, path traversal e enxurradas no xmlrpc ou no wp-login. Adicione correlate=1 para achar arquivos modificados minutos depois do tráfego suspeito.

        

        

          
Verificações rápidasquickscan=1

          
Os esconderijos baratos dos invasores: PHP executável em wp-content/uploads, ganchos auto_prepend_file em .user.ini e .htaccess, mu-plugins que carregam sem precisar de ativação e arquivos PHP ocultos (começando com ponto).

        

        

          
Datas de modificaçãoscantimes=1

          
Arquivos alterados depois do resto do pacote, e PHP cuja data de modificação foi recuada com touch enquanto o ctime do inode ficou onde estava. São pistas, não provas.

        

        

          
Crontabscancron=1

          
O crontab do usuário atual, verificado em busca de persistência: decodificadores base64 encadeados por pipe, downloads do pastebin e droppers em diretórios tmp.

        

      

    


    

      
Proteções que ele nunca quebra

      
Ele roda em servidores já comprometidos, então trata todo nome de arquivo, linha de log e resposta de API como hostil.


      
    
        
  • 
          Simulação é só simulação
          
    dryrun=1 vale para toda escrita, exclusão e restauração. Ele relata o que faria e não toca no disco.
    
        
    • 
        
  • 
          Restaurações são verificadas antes
          
    Cada arquivo do zip oficial é conferido byte a byte com os checksums de referência antes de ser gravado. Um pacote adulterado é recusado.
    
        
    • 
        
  • 
          Arquivos desconhecidos nunca são apagados
          
    Arquivos sobrando são reportados, e apagá-los é decisão sua. Use quarantinedir= para guardar cada original como evidência antes de sobrescrevê-lo.
    
        
    • 
        
  • 
          Gravações não truncam arquivos
          
    Arquivos limpos são gravados num arquivo temporário e renomeados no lugar, então uma gravação que falha deixa o original intacto.
    
        
    • 
        
  • 
          A verificação TLS fica ligada
          
    Um "tudo limpo" jamais pode vir de um invasor posicionado entre o servidor e o wordpress.org.
    
        
    • 
        
  • 
          Palpites nunca tocam no disco
          
    Achados de datas e de correlação com logs são pistas para você seguir. Nunca disparam uma limpeza ou restauração.
    
        
    • 
      

    


    

      
Saída pronta para pipe

      
Uma linha por achado, no mesmo formato em todos os scanners, pronta para grep, jq e tickets.


      

        

          
Texto

          
Os três primeiros campos nunca contêm vírgulas. Caminhos e conteúdo de logs vêm do servidor comprometido, então caracteres de controle e vírgulas em caminhos são codificados com %. Um nome de arquivo malicioso não consegue forjar uma linha de achado.

          
SEVERITY,TYPE,path,detail

        

        

          
JSON

          
format=json imprime um evento por linha no stdout e manda o progresso para o stderr, então o stdout continua legível por máquina.

          
{"event":"finding","severity":"HIGH",
 "type":"LOG_IOC","path":"...","detail":"..."}

        

      


      
O que o código de saída diz

      
    
        
  1. 0
    Limpo, ou só achados informativos.
    2. 
        
  2. 1
    Erro de uso ou fatal. Confira os argumentos.
    3. 
        
  3. 2
    Achados LOW, MEDIUM ou ERROR para revisar.
    4. 
        
  4. 3
    Achados HIGH. Uma limpeza bem-sucedida também sai com 3: havia malware.
    5. 
      

    


    

      
Leve até o servidor

      
Sem dependências e sem build. Copie um arquivo e rode.


      

        

          
    
            
  • PHP 5.6 ou mais novo. A extensão zlib só é necessária para logs .gz, e a zip só para verificar temas e restaurar arquivos.
    • 
            
  • Acesso ao shell, ou a possibilidade de subir um arquivo PHP e acessá-lo por HTTP.
    • 
            
  • Sem shell? Defina um WEB_ACCESS_TOKEN longo e aleatório no topo do arquivo, passe-o como ?token= e apague o arquivo quando terminar.
    • 
          

          

            
Faça backup antes de limpar. Simule antes com dryrun=1.

            
Ele encontra malware conhecido. Uma varredura limpa não prova que o site está limpo, e os alertas de log incluem muitas tentativas que falharam.

          

        

        

          

            
$ php elderward.php dryrun=1 scandirectory=/path/to/site

            
          

          

            
$ php elderward.php scanlog=/var/log/apache2 correlate=1 scandirectory=/path/to/wp-root

            
          

          

            
$ php elderward.php scanintegrity=1 restore=1 quarantinedir=/safe/place scandirectory=/path/to/wp-root

            
          

          

            
$ php elderward.php help=1

            
          

        

      

    


    

      
Envie o que ele deixou passar

      
O Elderward só conhece malware que alguém já pegou. Se você limpar um site e achar algo que ele não apontou, abra uma issue no GitHub com uma amostra para que a próxima varredura pegue.


      

        

          
O que colocar na issue

          
    
            
  • O arquivo, compactado em zip com a senha infected para que antivírus e GitHub não o removam. O GitHub não aceita um anexo .php solto.
    • 
            
  • O hash SHA-256 e o caminho onde você o encontrou.
    • 
            
  • Como ele era carregado: um include no functions.php, um mu-plugin, uma entrada no cron, auto_prepend_file ou outra coisa.
    • 
            
  • As versões do WordPress, dos plugins e do tema, se você tiver.
    • 
            
  • Para tráfego de ataque, as linhas correspondentes do log de acesso.
    • 
          

        

        

          
Prepare a amostra

          

            
$ shasum -a 256 suspicious.php

            
          

          

            
$ zip -j -P infected sample.zip suspicious.php

            
          

          

            
Issues são públicas. Remova tudo o que identifique o site antes de enviar.

            
Isso inclui nomes de domínio, credenciais do banco, salts, endereços de e-mail e IPs de visitantes nas linhas de log. Nunca anexe o wp-config.php nem um dump do banco.
